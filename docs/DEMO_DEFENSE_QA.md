# Короткі відповіді для комісії

Відповіді нижче описують реалізовану реконструйовану модель та збережені результати. Вони не приписують невідомі відповідності першоджерелу.

1. **Що таке TCM?** Це згорткове кодування, поєднане з вибором точки сузір’я. У цьому проєктному encoder двом інформаційним бітам відповідають три вихідні біти для 8PSK.

2. **Чому використано 8PSK?** У межах моделі кожна точка задається трьома фазовими бітами, тому це узгоджується з трьома вихідними бітами encoder. Це обрана модель, а не твердження про реальний HF-модем.

3. **Чому модель має чотири приховані стани?** У реалізованій trellis пам’ять encoder має два біти; чотири можливі комбінації утворюють чотири canonical state IDs. Слово «приховані» описує графічне представлення станів, а не підтверджує author-defined HMM.

4. **Що означають 16 переходів?** Кожен із чотирьох станів має чотири можливі двобітові входи, отже таблиця містить 4 × 4 канонічні переходи. Кожне ребро фіксує source, input, три output bits і target.

5. **Чому модель не paper-exact?** У доступному джерелі недостатньо даних, щоб однозначно підтвердити локальне edge-to-phase mapping та деякі часові й інноваційні конвенції. Вони явно позначені як реконструкції; `paper_exact:false`.

6. **Чим ця решітка відрізняється від повного HMM?** GUI показує canonical finite-state transitions і conditional Viterbi за замороженими метриками. Тут не оцінюється повна авторська transition/emission модель; не реалізовано forward-backward чи Baum–Welch.

7. **Як обчислюються метрики?** B4d формує по одній `F_rx` метриці для кожної з 16 гіпотез, порівнюючи восьмисемплові observed-IQ і predicted-IQ послідовності. Це конкретна метрика реконструкції реалізації, не автоматично метрика першоджерела.

8. **Що таке posterior?** Це нормовані ваги 16 гіпотез після застосування попередніх ваг та project pseudo-likelihood. Їх сума для поточного кроку дорівнює 1.

9. **Як працює рекурсивний оцінювач?** Реалізація формує pre-update state, прогнози, метрики й posterior, далі innovation та post-update state. Наступний символ використовує вже оновлений стан. Точна авторська семантика innovation не підтверджена.

10. **Для чого потрібен Viterbi?** Conditional Viterbi знаходить найдешевший допустимий шлях станів/ребер за послідовністю причинних метрик, замороженою з receiver trace. Це не спільна оптимізація прихованої траєкторії каналу.

11. **Чим frozen B відрізняється від anchored?** Frozen B використовує зафіксовану історичну політику `alpha′=1`, `K̃=[0,0]`, `mu0=[0,0]`, `beta=0.7`. Anchored policy використовує конфігурацію `alpha′=0.85`, `K̃=[0.0875,-0.05]`, `mu0=[0.42,0.91]`, `beta=0.7`; початковий fluctuating state дорівнює нулю. Ці числа — policy settings, не оцінені фізичні параметри.

12. **Чому адаптивний режим не завжди кращий?** Загальної переваги не встановлено. M9/M10 point estimates нижчі для anchored у зазначених контрастах, але обидва 95% intervals включають нуль; причина чи універсальна перевага з цього не випливає.

13. **Що означає BER?** Частка помилкових інформаційних бітів серед усіх порівнюваних бітів.

14. **Що означає SER?** Частка помилкових двобітових інформаційних символів серед усіх порівнюваних символів у визначенні цього проєкту.

15. **Чому confidence interval містить нуль?** У збереженому парному bootstrap інтервалі є як від’ємні, так і додатні різниці DeltaBER. За цим 95% interval не встановлено напрям статистично підтвердженої різниці; це не доводить рівність політик.

16. **Чи підтверджено перевагу anchored?** Ні. M9b DeltaBER = −0.0011328125, 95% CI [−0.00322265625, 0.00068359375]. M10b P1 DeltaBER = −0.0003125, 95% CI [−0.00205126953125, 0.0014453125]. Обидва інтервали включають нуль.

17. **Чи моделюється реальний HF-канал?** Ні. Demo використовує нормовану 8PSK, фіксований gain і заданий детермінований шум. M10 — контрольований evaluation-side piecewise-gain профіль, не фізична HF propagation model і не радіозв’язок.

18. **Які головні обмеження?** ADR-002 mapping і ADR-005 pseudo-likelihood реконструйовані; ADR-016 застосовується лише evaluation-side. SCI-02, SCI-03 і SCI-METRIC-02 відкриті. Демонстраційний BER/SER — один fixture; для paired inference потрібні незалежні archived runs. M5j не містить per-symbol estimator trace.
