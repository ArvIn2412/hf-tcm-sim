# GUI-ENERGY-01B — звіт про інтеграцію енергетичного аналізу

## Висновок

**Статус: `GUI_ENERGY_01B_READY_WITH_LIMITATIONS`.** Одиничний запуск показує обчислену з переданих samples енергію, а статистичний режим залишається окремою явною дією з opt-in автоматичним переходом. У Scientific Workspace відкривається перевірена історична серія SCIENTIFIC-EXP-01; provenance перевіряється, результати gain/CI заново обчислюються з парних trial records і показуються в GUI. Нову велику confirmatory-серію не запускали.

Математичний backend передавача, каналу, приймачів, метрик і декодера не змінювався. `paper_exact:false` збережено. Дискретна шкала не є автоматично фізичним Eb/N0.

## Що змінено

- Додано read-only endpoint для історичної серії: `/api/scientific/energy-studies/historical/static-amplitude-005`.
- Додано provenance-перевірку archive SHA-256/розміру, analysis manifest, gains, 140 записів trials, їхніх manifest/config/NPZ hashes, унікальності 7×20 плану та однакових observation hashes для Joint/B0/B1.
- Сервер заново обчислює цільові перетини й paired cluster bootstrap із зафіксованими seed/кількістю повторів та звіряє їх зі збереженим аналізом.
- Графіки BER і SER мають лінійну вісь `[0,1]`, нульові виміряні точки залишаються на нулі з поясненням, що нуль помилок у скінченній вибірці не доводить `P=0`.
- Легенди винесені окремо від полотен; кожну receiver-серію можна вмикати незалежно. Підписи осей і станів — українською.
- Додано PNG та SVG завантаження для чотирьох енергетичних графіків. SVG містить вбудований растр того самого canvas-графіка; він XML-валідний і масштабується як контейнер, але елементи графіка не є векторними.
- Одиничний результат очищає попередні графіки серії, щоб не змішувати вимірювання різних запусків.
- У статистичній вкладці режим автозапуску після одиничного моделювання вимкнений за замовчуванням. Коли його явно ввімкнено, запускається задана обмежена серія на тому самому Monte Carlo механізмі.
- Для відсутнього перетину GUI пояснює, що target BER не досягнуто в дослідженому діапазоні, і пропонує ручне розширення; заморожена сітка автоматично не змінюється.

## Перевірка одиничного запуску

У Microsoft Edge запущено Identity кадр `F=32` із `A=1`, вісьмома комплексними відліками на елемент і нульовим шумом. GUI показав:

- 256 переданих комплексних відліків;
- фактичну енергію переданого сигналу `256`;
- енергію на інформаційний біт `4`;
- `E_b,d = 4A²` збігається з фактичними samples;
- дисперсія шуму `0`, тому нормоване відношення не визначається;
- інформаційну швидкість `2 біт/елемент`;
- Joint і B0: `0/64` помилкових бітів та `0/32` помилкових інформаційних пар.

Це один кадр, не оцінка ймовірності та не оцінка енергетичного виграшу.

## Історична серія та незалежне звірення

У GUI відкрито саме збережену confirmatory static amplitude sweep SCIENTIFIC-EXP-01: сім точок енергії, 20 незалежних парних кадрів на точку, 140 записів. Trial-level observation hashes однакові для Joint/B0/B1. Backend loader перевіряє походження й повторно викликає той самий науковий аналіз із зафіксованим bootstrap seed; інтеграційний тест звіряє числові значення з `gains.json`.

Target `BER=0,05`:

| Порівняння | Потрібна `E_b,d` спільного приймача | Потрібна `E_b,d` окремого приймача | Модельний виграш | 95% paired bootstrap CI |
|---|---:|---:|---:|---:|
| Joint / B0 | 1,3528069307 | 6,4270986601 | 6,7677914708 dB | [6,2097559376; 7,5181654053] dB |
| Joint / B1 | 1,3528069307 | 2,6770140469 | 2,9641483046 dB | [2,7155971812; 3,2287690091] dB |

Інтерполяція виконана лише між виміряними точками. CI побудовано парним bootstrap за кадрами; для кожного порівняння маємо 1000/1000 валідних повторів. Це історичні **модельні дискретні** оцінки, а не нові GUI acceptance результати, не фізичний Eb/N0 і не підтвердження 1,5 dB зі статті.

## Реальна браузерна перевірка

Скрипт `scripts/qa_gui_energy_01b.js` керував Microsoft Edge через DevTools Protocol. Перевірено у вікнах 1366×768 і 1920×1080:

- запуск Identity і негайне відображення енергії/BER/SER;
- provenance-validated відкриття історичної серії, ціль BER, точки перетину, gain/CI та `[0,1]` шкали;
- перемикання серій у легенді;
- PNG/SVG експорт усіх чотирьох енергетичних графіків;
- запуск короткої статистичної серії, stop і resume без дублікатів, paired hashes;
- збереження/повторне відкриття;
- явний opt-in автозапуску обмеженої серії після одиничного кадру.

Короткі GUI acceptance trials зберігаються окремо в `outputs/repro09/energy-studies/`; вони не включені до історичного масиву, на якому наведено gain/CI.

## Обмеження

- Не виконувалась нова confirmatory-серія й не оцінювався новий енергетичний виграш.
- GUI історично відкриває тільки перевірений static-amplitude target 0,05 набір; це не універсальний переглядач довільних результатів.
- Результати залежать від дискретного означення `E_b,d`, амплітудного sweep, static multipath конфігурації й інтерполяційно-bootstrap протоколу SCIENTIFIC-EXP-01.
- `gamma_b,d` не оголошується фізичним `Eb/N0`; повна тотожність моделі статті не встановлена, `paper_exact:false`.
- SVG зараз є валідним контейнером із вбудованим растровим canvas, а не повністю векторним plot.
- Root-wide Ruff traversal не використовувався як критерій цього acceptance; пройшов scoped Ruff для змінених Python-компонентів.
