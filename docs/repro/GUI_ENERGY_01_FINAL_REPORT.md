# GUI-ENERGY-01 — звіт інтеграції енергетичного аналізу

## Висновок

**Статус: GUI_ENERGY_01_PARTIAL.** Scientific Workspace показує енергію фактичних відліків після одиничного запуску та запускає енергетичну серію через наявний механізм Monte Carlo. Відновлення, збереження, відкриття й графіки перевірені через Edge. Короткий приймальний набір не визначив BER-перетинів, тому енергетичний виграш і його довірчий інтервал для цього набору **не оцінюються**. Розрахунок виграшу/CI на виміряній GUI-серії з валідними перетинами не пройшов browser acceptance; це не результат основного confirmatory дослідження.

Значення `paper_exact:false` збережене. Фізичний `Eb/N0` і результат статті 1,5 дБ не підтверджуються цим GUI-тестом.

## Інтеграція

- Одиничний запуск передає фактичний масив `tx_samples` до презентаційного енергетичного адаптера. Для кадру з F символів обчислюється `E_tx,d = Σ|x[n]|²`, а `E_b,d = E_tx,d/(2F)`. Адаптер перевіряє конфігурацію 8 відліків на символ і 2 інформаційні біти на символ, включно з тотожністю `E_b,d = 4A²` для цього профілю передавача.
- Відображаються виміряна енергія кадру, енергія на біт, амплітуда, комплексна дисперсія шуму, дискретна енергетична шкала та інформаційна швидкість. Для нульового шуму шкала не визначається.
- Енергетична серія викликає наявні `EnergyTrialSpec`/`run_energy_trial` та `analyze_energy_records`; нових кодера, каналу, приймача, метрики чи bootstrap реалізацій немає. GUI фіксує конфігурацію, створює незалежні seed-namespace, використовує одне спостереження для всіх обраних приймачів у кожному кадрі та зберігає перевірювані trial manifests.
- Амплітудний sweep змінює A за фіксованої дисперсії; noise sweep змінює дисперсію за фіксованої A. Обидва режими використовують одну збережену конфігурацію каналу. B1 можна обрати лише в підтримуваних профілях; для Rician AR(1) він відхиляється.
- BER/SER-криві будуються лише із завершених кадрів. Енергетичний виграш показується лише за виміряного перетину в діапазоні сітки та виконання статистичних умов; екстраполяція не застосовується. Короткі серії явно маркуються розвідувальними.
- На вкладці ефективності наведено дискретні показники `ε_info = правильно декодовані біти / елементи сигналу` та `ε_energy = правильно декодовані біти / E_tx,d`. Це проєктні безрозмірні характеристики; вони не є фізичними біт/с або ватами.

## Контрольні запуски

### Одиничний Identity

Фактичний запуск через Edge: F=32, A=0,5, 8 відліків/символ, без шуму. Передавач видав 256 комплексних відліків. Виміряно `E_tx,d=64`, 64 інформаційних біти, `E_b,d=1`, що збігається з `4A²=1`. `σ²_c=0`, тому `γ_b,d` коректно показано як невизначене. Joint: 0/64 бітових і 0/32 парних помилок; B0: 0/64 та 0/32 відповідно. Хеш спостереження спільний. Показані GUI-часи кадру: приблизно 0,067 с (Joint) і 0,003 с (B0); це вимірювання одного короткого запуску, не оцінка складності.

### Парний static-multipath GUI acceptance

Фактично запущена й відновлена через Edge серія `gui-energy-01-edge-1794389260217`: static multipath із затримками `[0,3]`, коефіцієнтами `[(0.8+0j),(0.2-0.1j)]`, `σ²_c=0,05`, F=32, A-профіль із фіксованим шумом, ціль BER=0,05, сітка `γ_b,d = [-3,0,3] дБ`, 10 незалежних кадрів на точку, Joint+B0+B1. Під час QA серію зупинено на 1/30 завершених пар, а потім відновлено.

Це невеликий acceptance-набір: 10 кадрів на точку, тому позначений розвідувальним. Усі BER перевищують target 0,05 на виміряній сітці; перетин відсутній для Joint, B0 і B1. Для Joint/B0 та Joint/B1 немає оцінки необхідної енергії, gain або 95% CI; 500 bootstrap повторів не мають валідних перетинів. Не можна трактувати відсутність перетину як BER floor.

У кожній з 30 спроб було по одному observation hash для всіх трьох приймачів; перевірено 30 унікальних trial IDs і точну відповідність агрегованого BER сумам помилок. Повторне завантаження викликало production `load_energy_study`, який перевірив верхній manifest, конфігурацію, trial manifests, записи й observation hashes. Виміряний час серії — 10,137 с за бюджетом 300 с.

## Edge, графіки й артефакти

Перевірено Microsoft Edge через DevTools Protocol у розмірах 1366×768 та 1920×1080: автоматичний статистичний запуск не відбувається; немає горизонтального переповнення; Identity запускається з GUI; статистичну серію можна зупинити й відновити; результати повторно відкриваються; фактичні BER/SER відображаються. PNG BER-графіка має 593×250 пікселів, 148250 непрозорих пікселів і 12650 не-білих пікселів. Це підтверджує видимий вміст, а не лише наявність файла.

Для енергетичних графіків UI надає PNG-експорт; векторний SVG-експорт енергетичних кривих не реалізований і не перевірявся. Наявний SVG-експорт решітки Вітербі є окремою функцією та не замінює відсутній SVG для energy charts.
