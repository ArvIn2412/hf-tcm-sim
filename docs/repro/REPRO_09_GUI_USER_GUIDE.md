# REPRO-09 Scientific Workspace — короткий посібник

## Уточнення після REPRO-10A

У картках приймачів показані окремо:

- **BER** — кількість помилкових decoded information bits / кількість порівнюваних information bits.
- **SER інформаційних пар** — пара помилкова, якщо помилковий хоча б один із двох decoded bits; знаменник — кількість порівнюваних пар.
- **SER фаз 8PSK** — помилки індексів 8PSK phase symbols. Для B0 це hard decisions до Viterbi, тому ця величина може бути більшою або меншою за pair errors і не є information-pair SER.

Старе поле `ser` залишене у збережених summaries для сумісності; нові поля `information_pair_ser` та `phase_symbol_ser` мають явні значення. Історичні summaries можуть бути збагачені під час завантаження за збереженими decoder bits без переписування оригінальних файлів.

PNG/SVG кнопки активуються після готовності відповідного графіка. PNG має непрозорий білий фон; решітку Вітербі можна експортувати у SVG. Великі збережені traces залишаються lazy-loaded.

## Одиничний запуск

На вкладці **Параметри** задайте короткий кадр, seed і профіль каналу. Для першого запуску достатньо preset значень і кнопки **Запустити моделювання**. GUI запускає справжній REPRO-02 передавач, REPRO-03 канал, Joint REPRO-06C і B0 REPRO-04; для Identity або публічно заданих статичних taps можна увімкнути B1 REPRO-08. B1 не підтримує Rician і недоступний для нього.

Отримані дані доступні у вкладках **Передавач**, **Канал**, **Спільне приймання**, **Роздільне приймання**, **Решітка Вітербі** та **Порівняння**. Спільний вибір символу `k` відповідає відлікам `n=8k+i`; окреме керування дозволяє перейти до абсолютного sample index. Внески останніх delayed samples позначаються як channel tail, а не як новий символ.

## Решітка та η=20

На вкладці **Решітка Вітербі** оберіть receiver і символ. Екран показує реальні branch metrics, accumulated metrics, selected/rejected transitions, survivor edges та локальний traceback. Endpoint dropdown дозволяє простежити survivor для конкретного trellis state. Для звичайного Encoder A показується 4-state/16-edge решітка; для підтримуваної multipath `[0,3]` конфігурації — фактична augmented trellis 17/68.

`η=20` — це 20 trellis transitions. Окремий **20-sample zoom** показує комплексні відліки й не є traceback depth. Emitted finite-depth decisions, endpoint survivor trace і реконструйований edge із emitted bits позначені окремо.

## B1 та парне порівняння

B1 — channel-aware hard Hamming receiver з REPRO-08, який отримує лише явно задані публічні static taps. Він доступний для підтримуваних Identity/static конфігурацій; для часово-змінного Rician каналу GUI вимикає його. B0 не отримує ISI compensation. Joint, B0 та доступний B1 запускаються на одному `ReceiverObservation`; hash показано у порівнянні. BER/SER одиничного кадру — лише описові підрахунки.

## Monte Carlo

Вкладка **Monte Carlo** використовує REPRO-07 runner (Joint + B0): noise variance grid є sample-domain complex noise variance, не Eb/N0. Задайте frame length, trials на точку, seed та бюджет. Відновлення використовує те саме experiment ID і заморожену конфігурацію. **Зупинити після пари** завершує поточний paired trial, фіксує checkpoint, а наступний запуск продовжує серію. На графіках відображаються тільки завершені trials; короткі серії позначаються як exploratory.

## Збережені й довгі результати

Вкладка **Збережені** відкриває одиничні результати після перевірки manifest/hash. **Відкрити великий результат** відкриває наявні F=20,000 REPRO-08 BER/SER та окреме REPRO-06C Viterbi trace з lazy loading. Ці архіви мають різні observation hashes, що GUI показує явно; повної I/Q traces в них немає, тому вони не об'єднуються в один paired viewer.

Дані noise, оцінок і BER залишаються project-defined та source limitations з REPRO-08 незмінними. `paper_exact:false`; 1.5 dB — лише статейне historical claim, не результат цього GUI.

## Експорт графіків

Кнопка **Зберегти PNG** над графіком завантажує PNG із фактичного canvas поточного результату. Ім'я містить ID запуску, графік і вибраний символ. Для точного аналізу використовуйте числові масиви результату; зменшення даних у canvas стосується лише відображення.
# Науковий інтерфейс

```powershell
python -m hf_tcm.repro.scientific_studio --port 18771 --no-browser
```

Потім відкрийте `http://127.0.0.1:18771/scientific`. У вкладці «Параметри» задайте довжину кадру, канал, дисперсію шуму та seeds; для статичних коефіцієнтів відкрийте «Додаткові параметри». Виберіть B1 лише для підтримуваного статичного профілю й натисніть «Запустити моделювання».

Глобальні поля «Символ», «Відлік» і «Приймач» синхронізують дослідницькі вкладки. Знак `?` відкриває коротке пояснення параметра. У решітці Вітербі можна змінювати кінцевий стан шляху й фільтр показаних переходів; η рахує переходи, а не відліки.

Дисперсія задається у комплексній sample-domain конвенції й не є фізичним Eb/N0. Вбудована Rician AR(1) модель є проєктним профілем. Статус точності статті, невизначеність метрики та межі енергетичного порівняння описані у наукових звітах.

## Енергетична ефективність і статистичне дослідження

Після одиничного запуску відкрийте вкладку **Енергетична ефективність**: вона показує сумарну дискретну енергію фактичних переданих відліків, енергію на інформаційний біт, амплітуду, комплексну дисперсію шуму та дискретну шкалу. Для нульового шуму відношення до шуму не визначається. Поточний передавач має 8 комплексних відліків і 2 інформаційні біти на елемент, тому перевірка показує `E_b,d = 4A²` за фактичним масивом.

У **Статистичне дослідження** задайте F, сітку `γ_b,d`, цільовий BER, незалежні кадри на точку, seed-план, часовий бюджет, режим sweep і доступні receiver arms. Серія запускається лише явним натисканням; кнопка зупинки фіксує поточну пару, повторне натискання запуску відновлює checkpoint. Збережені завершені або перервані серії відкриваються через список. Joint/B0/B1 кожного кадру використовують спільне спостереження; B1 дозволено тільки на підтримуваних статичних каналах.

Амплітудний режим змінює A при фіксованій дисперсії шуму; шумовий режим змінює дисперсію при фіксованій A. Графіки використовують тільки завершені кадри. Короткі набори явно позначаються розвідувальними; якщо виміряної точки перетину з target BER немає, інтерполяція, енергія перетину, виграш і CI не показуються. `γ_b,d` і `E_b,d` належать до дискретної проєктної конвенції й не є автоматично фізичним Eb/N0.

Контроль інтеграції, таблиця вимірювань і відомі обмеження: `docs/repro/GUI_ENERGY_01_FINAL_REPORT.md`. Реальні приклади acceptance outputs зберігаються у `outputs/repro09/energy-studies/`; попередні результати `outputs/scientific_exp_01/` не змінюються.

### Перевірена історична оцінка енергії

На вкладці **Енергетична ефективність** натисніть **Відкрити перевірену серію**, щоб завантажити контрольну static-amplitude серію з SCIENTIFIC-EXP-01. GUI перевіряє походження, маніфести, hashes і повторно обчислює точки перетину та парні довірчі інтервали. Це відкриває дискретні модельні оцінки з історичних даних, а не запускає нове статистичне дослідження.

Одиничний запуск показує фактичну енергію переданих відліків і `E_b,d`; з одного кадру виграш не оцінюється. Вкладка **Статистичне дослідження** запускає серію лише після явного натискання. Автоматичний перехід після одиничного запуску вимкнений за замовчуванням і працює лише після увімкнення опції.

Енергетичні графіки підтримують PNG та SVG завантаження. Поточний SVG зберігає реальний canvas-графік як вбудоване зображення. Дискретна `gamma_b,d` не є фізичним `Eb/N0`; див. `docs/repro/GUI_ENERGY_01B_FINAL_REPORT.md`.
