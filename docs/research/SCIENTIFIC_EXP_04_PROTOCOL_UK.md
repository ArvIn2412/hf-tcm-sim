# SCIENTIFIC-EXP-04 — протокол: Хемінг vs Евклід у відомому тракті

Статус: **FROZEN → EXECUTED** (SHA-256 `25abdd72947c33754dc4fd04bf9b0e5b45d517ed10d45a22a8cec6fce99801d4`;
підтверджувальну серію виконано — результати: `SCIENTIFIC_EXP_04_RESULTS_UK.md`).
Розділ 4 нижче — розвідувальний пілот до заморожування.
Машинний протокол: `configs/SCIENTIFIC_EXP_04_PROTOCOL.json`.
Виконання: `scripts/run_scientific_exp04.py`, модуль `hf_tcm.repro.exp04_protocol`.

## 1. Мета і гіпотези

Порівняти два способи приймання TCM/8PSK (R = 2/3, 4 стани, η = 20) на
**однакових спостереженнях**:

* **Хемінг** — роздільні демодуляція (жорстке рішення 8PSK → 3 біти) і
  декодування Вітербі з метрикою Хемінга;
* **Евклід** — спільні демодуляція й декодування: Вітербі з м'якою
  евклідовою метрикою `P_k·|z_k − s|²` (зважена за станом тракту, ≡ `Σ|y − ĥs|²`).

| Гіпотеза | Формулювання | Статус |
|---|---|---|
| H1 (первинна) | В усіх первинних комірках Евклід потребує меншого Eb/N0, ніж Хемінг, при первинному цільовому BER; нижня межа 95 % ДІ виграшу > 0 | підтверджувальна |
| H2 | У завмираннях ITU moderate зважена евклідова метрика не гірша за незважену | описова |
| H3 | З причинною оцінкою каналу за пілотами виграш Евкліда зберігається | описова |

## 3. Аналіз

* Виграш = Eb/N0(Хемінг) − Eb/N0(Евклід) при цільовому BER; лінійна
  інтерполяція в log10(BER) між сусідніми виміряними точками; без
  екстраполяції.
* Первинні цілі: BER = 10⁻³ (A1, A2), 10⁻² (A3, A4). Усі комірки
  додатково звітуються при 5·10⁻² (відповідність p′ₙ статті), 10⁻², 10⁻³.
* ДІ: парний bootstrap за кадрами-кластерами, **спільні кластери для всіх
  точок Eb/N0** (наслідок спільних випадкових чисел), 5000 повторів, seed 404404.
* Вердикти: `PRECISION_CRITERIA_MET` (≥ 95 % валідних bootstrap-перетинів і
  напівширина ДІ ≤ 0,5 дБ), `INSUFFICIENT_PRECISION`, `ENERGY_GAIN_NOT_ESTIMABLE`.
* 1,5 дБ статті порівнюється лише описово; `paper_exact = false`; нічого не
  підганяється.

Рішення за пілотом: крок 0,5 дБ там, де крива Евкліда різко падає в AWGN і
статиці; 400 кадрів для A1/A2 (≥ 100 помилок Евкліда при 10⁻³); 1000 кадрів
для завмирань, бо кадр 0,21 с охоплює приблизно одне завмирання (час
когерентності 0,75 с при 0,5 Гц).

Спостереження пілоту (перевірити в основній серії): S1 ≈ A3 — при
повільних завмираннях вага Σ|ĥ|² майже стала в межах вікна декодування,
тому зважування мало змінює рішення Вітербі.

## 5. Ресурси

Preflight (`run_scientific_exp04.py preflight`): вісь Eb/N0 точна в усіх
комірках (похибка < 10⁻⁹ дБ), ≈ 0,045–0,056 с на парний кадр, разом ≈ 1,3 год
декодування (з записом файлів — орієнтовно 2–3 год), ≈ 0,8 ГБ на диску.
Кожна комірка вміщується у свій бюджет часу (1 год для A1/A2, 3 год для
завмирань).

## 6. Порядок затвердження і запуску

1. Переглянути протокол (цей документ + JSON). Будь-яка зміна JSON змінює SHA-256.
2. Заморозити: `python scripts/run_scientific_exp04.py freeze`
   (створює `configs/SCIENTIFIC_EXP_04_PROTOCOL.json.sha256`).
3. Запустити з явним підтвердженням дайджесту:
   `python scripts/run_scientific_exp04.py run --approve <SHA-256>`
   (можна по одній комірці: `--cell A1-awgn`). Без збігу дайджесту й
   замороженого файлу раннер відмовляє. GUI підтверджувальні серії не запускає.
4. Аналіз: `python scripts/run_scientific_exp04.py analyze` →
   `outputs/scientific_exp04/analysis.json`.

## 7. Обмеження

* Затримки ITU (0,5–2 мс) не відтворені: другий промінь — 3 відліки (комбайнер
  чистого хвоста потребує затримки < 8 відліків).
* «Відомий тракт» — точні коефіцієнти каналу (genie CSI); практичний випадок — S2.
* Eb/N0 валідований для дискретної AWGN-моделі; смугові фільтри, синхронізація
  та форма імпульсу радіостанції не моделюються.
* Кодер і маркування — реконструкції проєкту (SCI-02), хоча відстані коду
  збігаються з оптимальним 4-станним кодом Унгербоека.
