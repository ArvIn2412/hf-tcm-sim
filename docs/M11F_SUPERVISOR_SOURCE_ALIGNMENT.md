## Висновок

У проєкті й статті v7 описані різні рівні подання згорткового кодера. У розділі 4 наведено Code 2 з 16 станами й 64 переходами для всіх чотирьох двобітових входів у кожному стані. Реалізація HF-TCM-SIM, узгоджена з рисунками 2–3 статті v7, має чотири стани й 16 переходів. Ці графи не можна ототожнювати чи зливати без окремого рішення про реалізацію й декодування.

## Придатність окремих channel-модулів

`channels/multipath.py` приймає явні `PathSpec` із integer delays, power і K-factor та повертає received samples окремо від `ChannelTruth`. Вона придатна як ізольований forward-model компонент для майбутнього sandbox. Наявний B4d receiver її не викликає; contract ADR-012 і candidate metric орієнтовані на один zero-delay path. Отже, підключення зараз змінить модель спостереження та receiver contract.

`channels/rician.py` підтримує static coefficients і явно approximate AR(1) для diffuse складової з переданим RNG. Це корисна керована інженерна модель, але сама по собі не реалізує невизначену fading recursion статті.

`channels/awgn.py` задає complex circular AWGN через `Eb/N0`, `bits_per_symbol`, `Es` і explicit NumPy generator. Її контракт орієнтовано на normalized symbol-rate experiments; він не еквівалентний без додаткового узгодження шуму на 8 ZOH-відліках і не є deterministic M11a noise fixture.

`channels/fluctuating_noise.py` реалізує джерельні AR(1) quadrature recurrences із формулами статті (9)–(10). Функція генерує лише I/Q noise processes, вимагає RNG і не збирає повний passband/channel model. Її доцільно досліджувати окремо від Rician diffuse fading; ці процеси не можна семантично ототожнювати.

## Точна межа інтеграції M11f

Signal Explorer працює лише поверх відповіді на явний M11a POST. Він читає actual input, transmitter arrays, per-symbol receiver trace, frozen metrics, candidate weights, estimator snapshots і full-frame Viterbi result. GET не запускає симуляцію. Жодний encoder, channel чи decoder алгоритм не змінено; Code 2 не подається як повноцінний receiver.
